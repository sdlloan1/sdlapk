# Setup notes

Two things live here:

- `app/` — the Android WebView app (Gradle + Kotlin). It can't be run in the sandbox.
- `server/` — the admin dashboard + config API (Express + Postgres), served on host port 3000
  by `docker-compose.base44.yml` (`python`/`node:22`, `node --watch` for reload).

`site/` is the static download page, mounted read-only into the web container and served at
`/download`.

## Contract between backend and app

`GET /api/config` returns `{ config: {...}, updatedAt }`. The Android client
(`AppConfig.kt` / `ConfigRepository.kt`) parses that same shape; keep field names in
`server/src/defaults.js` in sync when adding settings. The app caches the last good config in
SharedPreferences and falls back to built-in defaults.

The API base URL is baked in at build time from the `SDL_CONFIG_API` gradle property
(`app/build.gradle` → `BuildConfig.CONFIG_API`). Empty means "never call the network".

## Secrets

- `SESSION_SECRET` — signs dashboard sessions; a development value is generated by the
  platform and delivered in `/run/base44/app.env`.
- `ADMIN_PASSWORD` — dashboard password, set as a platform secret (a real value overrides the
  `admin123` development placeholder in `.env.base44-defaults`). To change it, update the secret;
  the web service is recreated automatically, no code change needed.

## Rebuilding the downloadable APK

`site/app-release.apk` is a committed build artifact. After changing Android code:

```bash
gradle assembleRelease
cp app/build/outputs/apk/release/app-release.apk site/app-release.apk
```

The sandbox host has no JDK/Android SDK, so build in a container (SDK already at
`/tmp/androidsdk`):

```bash
docker run --rm --user root -v "$PWD":/src -v /tmp/androidsdk:/sdk \
  -v /tmp/gradle-home:/gh -w /src -e ANDROID_HOME=/sdk -e GRADLE_USER_HOME=/gh \
  gradle:8.9-jdk17 bash -c 'echo sdk.dir=/sdk > local.properties && gradle assembleRelease --no-daemon'
```

## Verifying

- Dashboard: log in with the admin password, change a setting, press Save, then read it back
  from `GET /api/config` (that endpoint is what the app consumes).
- The dashboard shows the packaged launcher icon on a mock home screen; its artwork is
  `server/public/launcher-icon.png`, a copy of `app/src/main/res/mipmap-xxxhdpi/ic_launcher_foreground.png`
  over the brand gradient — refresh the copy after changing the Android icon.
- The target website sends `X-Frame-Options: DENY`, so it can never be shown in an iframe;
  the dashboard's "Open website" link opens it in a new tab instead.
- Android changes can only be checked in the packaged output:
  `aapt dump badging site/app-release.apk` (icon, portrait lock, versionCode).
- Reset the stack with `docker compose -f docker-compose.base44.yml down` (keeps the
  `pgdata` volume) if a container gets wedged by a port clash on 3000.

## Deploy

`render.yaml` is a Render Blueprint (web service + Postgres). `ADMIN_PASSWORD` is prompted on
first deploy; `SESSION_SECRET` is generated by Render.
